## 🧪 HTML-lint (проверка вёрстки в CI)

Цель: ловить битую вёрстку до деплоя, а не после.

### Как это работает

В `.github/workflows/` добавлен отдельный job (`html-lint.yml`), который запускается
при `push` / `pull_request` в `main` и проверяет `index.html` через `html-validate`
(или `htmlhint`, запускается через `npx`, без установки зависимостей в проект).

Если в HTML есть ошибки (незакрытый тег, невалидная вложенность, дублирующийся `id`
и т.п.) — job падает (красный статус), и битая вёрстка не уходит дальше по пайплайну.

### Тест-кейс: job падает на битой вёрстке и проходит на валидной

**Предусловия:** workflow `html-lint.yml` замержен в `main`, использует `html-validate`
для проверки `index.html`.

| № | Шаг | Ожидаемый результат |
|---|-----|----------------------|
| 1 | Открыть вкладку **Actions** | Новый job виден в списке workflows |
| 2 | Создать ветку `test/broken-html`, сломать тег в `index.html` (например, убрать `</div>` у `.card`) | Изменение закоммичено в ветку |
| 3 | Открыть PR из `test/broken-html` в `main` | Job линтинга запускается автоматически |
| 4 | Дождаться завершения job | Статус **failure** (❌), в логе — конкретная ошибка с номером строки |
| 5 | Сделать скриншот красного статуса и лога | Приложено к issue |
| 6 | Исправить тег в той же ветке, запушить fix | Job перезапускается |
| 7 | Дождаться завершения job | Статус **success** (✅) |
| 8 | Сделать скриншот зелёного статуса | Приложено к issue |
| 9 | Смержить PR в `main` | Job на `main` зелёный, деплой безопасен |

**Негативные проверки:**
- Незакрытый тег → должен упасть
- Невалидная вложенность (`<p><div>...</div></p>`) → должен упасть
- Дублирующийся `id` на странице → должен упасть

**Критерии приёмки:**
- ✅ Job виден во вкладке Actions
- ✅ Есть скриншот/лог упавшего прогона
- ✅ Есть скриншот/лог успешного прогона
- ✅ Оба приложены к issue
